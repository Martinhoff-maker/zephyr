 * while the final programmed hardware state remains equivalent to the
 * current DTS + driver + HAL behavior.

================================================================================
OVERVIEW
================================================================================

The siwg917-clean.dtsi exposes THREE physical clock manager nodes:

1. hp_clock_manager @ 0x46000000
  - HP clock-control block
  - Additional register windows:
    - misc-config @ 0x46008000
    - pll @ 0x46180000
  - Owns HP peripheral clocks and HP-specific static gate bits

2. ulp_clock_manager @ 0x24041400
  - ULP clock-control block
  - Owns ULP peripheral clocks and ULP-specific dividers/gates

3. aon_clock_manager @ 0x24048000
  - AON / NPSS reference-clock and LF control block
  - Owns RTC / watchdog domain and reference-clock switching relevant to sleep

This is a cleaner hardware description.

Critical rule: even if the DT representation is split, the final programmed hardware
configuration must stay equivalent to the current stack.

================================================================================
DRIVER ARCHITECTURE
================================================================================

Recommended clean architecture:

Option A: Multiple physical providers with the same flat clock IDs
  - hp_clock_manager, ulp_clock_manager, aon_clock_manager each use `#clock-cells = <1>`
  - Reuse the existing flat `SIWX91X_CLK_*` IDs
  - The meaning of the ID is provider-scoped
  - Example:
    - `<&hp_clock_manager SIWX91X_CLK_UART0>`
    - `<&ulp_clock_manager SIWX91X_CLK_ULP_UART>`
    - `<&aon_clock_manager SIWX91X_CLK_RTC>`
  - Keeps the DT readable without forcing a new enum namespace

Option B: One aggregator driver above three physical managers
  - Possible, but adds indirection without improving the hardware description

The key point is not how many providers exist in DT. The key point is that the same
physical clocks are selected and programmed as today.

================================================================================
CLOCK CONFIGURATIONS IN REGISTERS
================================================================================

For each clock, the driver must handle:

1. Clock Source Selection
   - Via CLK_CONFIG_REGx registers
   - Sources: RC_32MHZ, XTAL_CLK, SOC_PLL, INTF_PLL, I2S_PLL, etc.
   - Register offset varies by clock type

2. Clock Divider (Prescaler)
   - CLK_DIV_FAC fields
   - Can be odd or even divisor
   - Odd/even selection via _ODD_SEL bits

3. Clock Gating (Enable/Disable)
   - CLK_EN_SET_REGx: Write '1' to enable
   - CLK_EN_CLEAR_REGx: Write '1' to disable
   - Per-clock granularity

4. Clock Status/Switching
   - PLL_STAT_REG: Check if clock has switched
   - Verify before accessing dependent blocks

================================================================================
IMPLEMENTATION SKELETON
================================================================================

Possible implementation styles:

1. Three clock drivers
  - `silabs,siwx91x-hp-clock-manager`
  - `silabs,siwx91x-ulp-clock-manager`
  - `silabs,siwx91x-aon-clock-manager`
  - Each driver stays small and domain-focused

2. One shared implementation file with three DT compatibles
  - Common helpers for HAL calls and rate calculation
  - Thin wrappers per domain

This is often the best compromise.

#include <zephyr/drivers/clock_control.h>
#include <zephyr/dt-bindings/clock/silabs/siwx91x-clock.h>
#include <zephyr/logging/log.h>

Implementation principle:
  - Split by physical block, not by logical consumer category.
  - Keep one shared helper layer for common HAL operations.
  - Preserve all existing side effects from the current driver.

================================================================================
KEY FUNCTIONS BY DOMAIN
================================================================================

HP clock manager must preserve existing behavior:
  - Processor clock (M4 core, up to 180 MHz)
  - QSPI flash controller
  - QSPI2 PSRAM controller
  - USART0 / UART1
  - SPI / SSI Primary
  - I2S audio
  - Timers (configurable)
  - MVP (Matrix Vector Processor)
  - Generic SPI Primary
  - DMA (DMA0, GPDMA)
  - RNG

ULP clock manager must preserve existing behavior:
  - MCU ULP AHB interface clock
  - UART (ULP)
  - SPI / SSI (ULP)
  - I2S Controller (ULP)
  - Timers (ULP)
  - Aux ADC / DAC Controller
  - UULP APB-related clocks used by ULP peripherals

AON clock manager must preserve existing behavior:
  - RTC
  - Watchdog

Important HAL behavior to keep:
  - clock init programs M4 core to SOC PLL and INTF PLL to 160 MHz
  - QSPI is switched to INTF PLL at init
  - sleep path (`sli_si91x_config_clocks_to_mhz_rc`) switches both M4 and ULP reference clocks through the AON/FSM block
  - the HAL change added an explicit wait for `M4_SOC_CLK_SWITCHED`
  - static I2S HP still touches the misc-config register block
  - static ULP I2S still programs `ULP_I2S_MASTER_SLAVE_MODE`
  - ADC still includes AUX power gating side effects

BINDING REQUIREMENTS
================================================================================

Suggested bindings:

bindings/clock/silabs,siwx91x-hp-clock-manager.yaml:
  compatible: "silabs,siwx91x-hp-clock-manager"
  include: [clock-controller.yaml]
  properties:
    reg:
      description: Register ranges [m4clk, misc-config, pll]
    reg-names:
      items:
        - const: m4clk
        - const: misc-config
        - const: pll

bindings/clock/silabs,siwx91x-ulp-clock-manager.yaml:
  compatible: "silabs,siwx91x-ulp-clock-manager"
  include: [clock-controller.yaml]
  properties:
    reg:
      description: Register range [ulpclk]
    reg-names:
      items:
        - const: ulpclk

bindings/clock/silabs,siwx91x-aon-clock-manager.yaml:
  compatible: "silabs,siwx91x-aon-clock-manager"
  include: [clock-controller.yaml]
  properties:
    reg:
      description: Register range [mcu-aon]
    reg-names:
      items:
        - const: mcu-aon

Each binding can still use `#clock-cells = <1>` and the same flat SIWX91X clock IDs.
